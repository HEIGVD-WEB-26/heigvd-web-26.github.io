Three layers: browser, network, server. Each layer has its own attack classes. We'll go top-down.

Same-Origin Policy

Two pages from different origins can't interfere.

http://a.comhttps://a.comNo (protocol)
https://a.comhttps://a.com:8443No (port)
https://a.comhttps://api.a.comNo (host)
https://a.comhttps://a.com:443Yes (443 is the default)
§2
Origin = scheme + host + port. Exceptions: images, scripts, form action — and explicit cross-origin via postMessage / CORS.

CORS

// Browser:                  // Server:
fetch('https://api.com',
      {method:'DELETE'}) ──▶ OPTIONS /  (preflight)
                          ◀── Access-Control-Allow-Methods: DELETE
                          ──▶ DELETE /  (real request)
                          ◀── 200 OK
§3
Enforced by the browser, not the server. Preflight only for non-simple methods/headers/content-types. Credentialed requests need both credentials:include and Allow-Credentials: true.

Cookies that don't get stolen

Set-Cookie: __Host-session=eyJ…;
            Secure; HttpOnly; SameSite=Lax;
            Path=/; Max-Age=86400
§4
Secure → HTTPS only. HttpOnly → invisible to JS. SameSite=Lax → modern default, blocks naked CSRF. __Host- prefix → enforces Secure+Path=/+no Domain. Use it.

CSRF (modern view)

<!-- evil.com -->
<form action="https://bank.com/transfer" method="POST">
  <input name="to"     value="attacker">
  <input name="amount" value="1000">
</form>
<script>document.forms[0].submit()</script>

SameSite=Lax (the modern default) closes this for POST. Tokens remain for defense in depth.

§5
Before 2020 this was an everyday bug. Now: naked CSRF on POST is closed by the default. But top-level GETs still travel under Lax, and older browsers / intranets need a CSRF token in depth.

XSS — reflected

// Server:
res.send(`<h1>Hello, ${req.query.user}</h1>`)

// URL:
?user=<img src=x onerror=alert(1)>
§6
Same pattern in stored XSS (content from the DB) and DOM-XSS (untrusted data → innerHTML on the client). The "img onerror" trick works even when innerHTML refuses to run script tags.

XSS — three pillars

  1. Escape on the way out — per context, via template engine
  2. CSP with nonces — script-src 'self' 'nonce-…'
  3. Trusted Types — structural fix for DOM-XSS
§6
Trusted Types is Chromium-stable. require-trusted-types-for 'script' makes innerHTML throw on raw strings — forces all DOM sinks through sanitizer policies.

§8
Attacker on the server doesn't go through your UI or browser. Parameterized queries for SQLi. Allowlist for SSRF. Generic error messages for leaks. Lockfile + audit for supply chain. And rate-limit everything.

Storing passwords

  • Hash, don't encrypt
  • Salt — random, per-user, stored with the hash
  • Slow function — bcrypt / scrypt / Argon2id
  • Use a library — "don't roll your own crypto"
§9
NIST 800-63B: no forced rotation, no composition rules, allow long passwords, block known-breached, rate-limit. Length beats complexity.

§10
JWT pitfalls: alg=none, algorithm confusion, payload is readable. OAuth2 PKCE: app generates verifier → hashes to challenge → exchanges code + verifier for token. WebAuthn: per-origin keypair in secure hardware, signature bound to origin → structurally ends phishing.

Five rules

  1. Never trust user data
  2. Complexity is the enemy of security
  3. Be explicit, fail fast
  4. Stack defenses
  5. Use the platform's good defaults
